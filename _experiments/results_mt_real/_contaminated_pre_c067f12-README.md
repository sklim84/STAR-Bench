# DuckDB 파일 락으로 오염된 실행 (재실행 전 원본)

`run_oracle_vs_real.sh` 가 모델을 GPU 마다 동시 실행하는데 `db.py` 가 DuckDB 를
읽기·쓰기로 열어 배타 락을 걸었다. 도구 실행 5,607건 중 3,136건(55.9%)이 에러이고
그중 2,381건(42.5%)이 `IO Error: Could not set lock on file ... HOFINET.duckdb` 다.

락 발생률이 어떤 모델이 언제 같이 돌았느냐로 갈려(0%인 설정 9개, 85% 이상 5개)
모델 간 비교가 성립하지 않는다. 또한 락은 시나리오를 조기 종료시켜 도구 실행 건수를
75~313 으로 깎았으므로 값만이 아니라 표본 자체가 훼손됐다.

`c067f12` 가 DuckDB 를 `read_only=True` 로 열도록 고쳤고, 같은 파이프라인을 다시 돌린
결과가 상위 디렉터리에 있다.

| 지표 | 이 디렉터리(오염) | 재실행 |
|---|---|---|
| 도구 실행 | 5,607건 | 5,410건 |
| 에러 | 3,136 (55.9%) | 30 (0.6%) |
| DuckDB 락 | 2,381 (42.5%) | **0건** |

어떤 분석에도 사용하지 말 것.
