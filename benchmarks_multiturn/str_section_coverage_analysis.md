# STR §VII 섹션 커버리지 분석 (멀티턴 시나리오 정답 기준)

## 1. 분석 목적

`cases_str_workflow.json` 50개 멀티턴 시나리오의 정답 `generate_str.summary`(이하 expected summary)가
한국 특정금융정보법 STR 양식 §VII (의심스러운 거래에 대한 서술부분) 7개 sub-section을
어느 정도 커버하는지 정량 분석한다.

본 분석은 두 가지 목적을 가진다.

- **벤치마크 설계 정당성 보강 (활용 A)**: 정답이 §VII 핵심 섹션을 충실히 커버하는지 검증하여
  멀티턴 시나리오가 STR 작성 워크플로우를 적절히 모사함을 보인다.
- **모델 평가 metric 정의 (활용 B의 사전 작업)**: 후속 모델 재실험에서 쓸
  §VII 섹션별 키워드 매칭 metric을 사전 정의한다.

## 2. STR §VII 정의 (08\_STR\_보고서양식.md 인용)

| 번호 | 섹션 | 필수성 | 내용 |
|---|---|---|---|
| §VII.1 | 의심스러운 거래자 관련 | 선택* | 거래자 배경 서술 |
| §VII.2 | 거래 발생일자 관련 | 선택* | 시기·기간 |
| §VII.3 | 거래 발생 장소(영업점) 관련 | 선택* | 출금/입금 영업점 |
| §VII.4 | 금융거래 수단(상품) 관련 | 선택* | 자금구분·매체구분 |
| §VII.5 | 금융거래 방법(특이거래) 관련 | 선택* | 패턴·이상 행태 |
| §VII.6 | 혐의거래로 판단한 사유 관련 | 선택* | 근거·증거 |
| §VII.7 | 종합의견 | **필수** | 6하 원칙 (누가·언제·어디서·무엇을·어떻게·왜) |

## 3. 방법론

### 3.1 입력

`_paper/benchmarks_multiturn/cases_str_workflow.json` 50개 시나리오 중
`generate_str` 도구 호출이 포함된 시나리오를 추출한다.

- 50 시나리오 중 **45개**에 `generate_str` turn 존재
- 5개 시나리오는 비-STR 워크플로우(비교용 또는 대화 종료 형태)

각 시나리오의 마지막 generate\_str turn에서 `expected.tool_calls[].arguments.summary` 텍스트를 추출한다.

### 3.2 §VII 섹션별 키워드 패턴

각 §VII 섹션은 정규식 패턴 집합으로 정의한다. 텍스트에 패턴 중 하나라도 매칭되면 해당 섹션 충족(1.0)으로 판정한다.

```python
SECTION_PATTERNS = {
    'VII.1 거래자': [
        r'계좌\s*\d+',                            # 계좌번호 (예: 출금계좌 78432)
        r'출금계좌|입금계좌',
        r'사업자|법인|개인',
    ],
    'VII.2 발생일자': [
        r'202\d년',                              # 연도
        r'20\d{6}',                              # YYYYMMDD
        r'\d+분기|\d+월|상반기|하반기',
        r'\d{1,2}~\d{1,2}시|\d{1,2}시|심야|새벽|오전|오후|저녁|당일|익일',
    ],
    'VII.3 발생장소': [
        r'출금금융회사|입금금융회사|금융회사\s*\d+',
        r'지점|영업점|기관',
    ],
    'VII.4 거래수단': [
        r'현금|수표|주식|채권|외환|이체|대체|전자화폐|유가증권',
        r'자금구분|매체구분',
        r'PC뱅킹|인터넷뱅킹|ATM|모바일|콜센터',
    ],
    'VII.5 거래방법(특이)': [
        r'심야|새벽|연속|반복|다수|복수|동시',
        r'분할|구조화|스머핑|smurfing',
        r'거액|고액|급격|급증|급변|패턴|이상',
        r'다중|chain|체인',
    ],
    'VII.6 혐의사유': [
        r'AI|예측|모델|확률|prob',
        r'이상거래|이상\s*확률|위험도|risk',
        r'네트워크|연결\s*계좌|군집|클러스터',
        r'\d+\.?\d*\s*%|\d+%',
    ],
    'VII.7 종합의견 (6하원칙)': {
        '누가':   [r'계좌\s*\d+|사업자|법인|개인|거래자'],
        '언제':   [r'202\d년|20\d{6}|분기|월|시|심야|새벽|당일|익일'],
        '어디서': [r'금융회사|지점|영업점|기관'],
        '무엇을': [r'거래|이체|입금|출금|송금|예금|환전|매수|매도'],
        '어떻게': [r'분할|반복|다수|연속|심야|현금|이체|패턴'],
        '왜':     [r'의심|혐의|자금세탁|범죄|불법|탈세|구조화|회피'],
    }
}
```

§VII.7 종합의견은 6하 원칙 6개 항목을 분리 측정하여 평균을 점수로 사용한다.

### 3.3 측정 단위

- 시나리오 단위: 각 §VII 섹션의 0/1 점수 (또는 §VII.7은 0~1 평균)
- 7섹션 평균 충족률: 시나리오의 7섹션 점수 평균
- 50 시나리오 평균 + 분포 + fraud\_type 분류

## 5. 해석

### 5.1 핵심 4섹션 80%+ 커버

§VII.1 거래자(100%), §VII.5 거래방법(97.8%), §VII.6 혐의사유(82.2%),
§VII.7 종합의견(평균 점수 0.748)이 4개 핵심 서술 섹션을 충실히 커버한다.
이는 멀티턴 시나리오의 정답이 STR 양식의 의무 서술 영역을 일관되게 반영함을 보인다.

### 5.2 §VII.3 발생장소 17.8% — 벤치마크 한계로 명시

`HOFINET` 데이터는 출금금융회사·입금금융회사를 일련번호(예: 134, 117)로 익명화하여 제공하기 때문에,
expected summary가 영업점·지점 정보를 자연어로 풀어 쓸 정보 자체를 갖지 못한다.
이는 데이터셋 비식별화에서 비롯한 구조적 한계이며, 본 벤치마크가 §VII.3 측정에
우선순위를 두지 않음을 시사한다.

### 5.3 §VII.4 거래수단 60% — 압축 표현의 결과

`자금구분`(예: 4=대체) 또는 `매체구분`(예: 7=전자화폐) 같은 코드값은
expected summary에서 자연어로 풀어 쓰는 대신 압축된 거래 행태 서술로 흡수되는 경우가 많다.
이는 summary의 압축 형식 특성에 기인한다.

### 5.4 fraud\_type 7 (심야/대량) 충족률 0.508 — 표본 작음

n=3으로 통계적 신뢰도가 낮다. 또한 심야 대량 거래 패턴 자체가 단순(시간대 + 금액 규모)이라
summary 길이가 짧아 §VII.4 거래수단·§VII.2 발생일자 외 섹션 충족이 어렵다.

### 5.5 정답 70.4% 충족이 갖는 의미

벤치마크 정답조차 7섹션 평균 70.4%만 충족한다. 이는 두 가지 함의를 갖는다.

- **본 벤치마크의 §VII 측정 metric은 정답 대비 상대 점수**로 해석되어야 한다.
- 모델 측정 시 모델 간 변별력이 충분히 나타날 가능성이 크다 (정답 70.4%, 모델은 30~65% 추정 범위).
